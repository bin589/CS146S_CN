## 第 12 页：最佳实践

**最佳实践**

- 保持范围聚焦。
  - 一个技能只做一件定义清晰的事。
- 维护自己的技能集合，使其能轻松迁移到不同项目。
- 挖掘你自己的对话记录。
  - 技能是用 Markdown 写成的流程——翻看你自己的聊天记录，找出你在哪里介入或纠正过 agent。
  - “厨师换厨房时，会带上自己的刀。”——poteto
- 不要把 token/时间浪费在重复造轮子上。
  - 给 agent 配一个 CLI 工具，再把样板流程包装成一个技能。

## 第 13 页：最佳实践

**最佳实践**

- 在技能中写明应该触发它的情境和请求措辞。
- 渐进式披露（Progressive disclosure）。
  - 按需引用特定文件，并附上额外上下文。
  - 把技能模块化并组合使用。
- 维护一个验证技能，让 agent 检查自己的工作。
  - 这样可以形成改进闭环。

## 第 14 页：API、MCP 与技能的区别

**API vs MCP vs Skills（API、MCP 与技能）**

**APIs**

- **是什么**：应用暴露给开发者调用的 HTTP/REST/GraphQL 服务接口。
- **谁来用**：你本人，或者某个 SDK。
- **使用方式**：认证、重试、分页、输入校验等都由你自己决定。

**MCP**

- **是什么**：服务器暴露的工具定义，让 LLM agent 能以标准化的方式调用。
- **谁来用**：模型/agent 运行时（以“工具调用”的形式），而不是每次都由人类开发者编写定制集成。
- **使用方式**：与外部资源、数据、服务交互的主要机制。

**Skills**

- **是什么**：可复用的任务包/流程，教 agent 如何完成一项工作，通常通过编排多个工具/端点来实现。
- **谁来用**：agent 或 agent 框架，把它当作可以主动取用的更高层能力。
- **使用方式**：工作流抽象——“这是完成 X 的可重复做法。”
